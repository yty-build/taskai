# Journal

## 2026-08-30 — Interface concept page (docs/interface_concept.html)

- Built the TaskAI UI concept as a living, keyboard-driven single-file HTML demo rather than static mock screens. Direction: "OLED cockpit glass" — dark-only, glass panels, one ion-blue accent, amber reserved for attention, red reserved for Destroy, HUD-style corner-bracket selection.
- Fonts are embedded as base64 woff2 data URIs (Switzer UI / Martian Mono HUD labels / Geist Mono terminal, ~137KB total) because artifact CSP blocks font CDNs. Sources: Fontshare API for Switzer, Google Fonts (latin subset URL requires a browser User-Agent header) for the monos.
- Python urllib fails behind the local proxy (self-signed cert in chain); curl works. Use curl for downloads in this environment.
- Playwright MCP blocks `file://` — serve the page with `python3 -m http.server` on localhost instead. Screenshots land in the repo root (`./name.png`); move them to the scratchpad to keep the repo clean.
- Feed engine gotcha: script loops must restart at an op that opens a visual block (a spinner or tool call), never at a `⎿` result line, or the loop orphans output. Same class of bug: cycling an arrow-select option that has a side effect (opening the repo explorer) must not fire while cycling *past* it — keep side-effect options last.
- Demo data must stay internally consistent: harness live counts, tree states, and home-row aggregates are all derived from one session list, so a "needs setup" harness cannot also have a live session (that's why the demo adds Aider as the unconfigured harness instead of Grok, which the UX doc uses).
- Four-lens critique workflow (aesthetic / CSS craft / product fidelity / interaction) surfaced 44 findings; ~35 applied. Highest-value: loop variance via `{{n:a-b}}`/`{{pick:…}}` templating in feed scripts (verbatim repetition kills the "living terminal" illusion), aurora hotspots must sit *under* the glass panels or backdrop-blur reads as flat cards, and ion must be reserved for live/selection (ready-states go dim).
- T direction: the terminal build must be a 100% replica of the HTML, building custom modules where stock TUI widgets fall short. Replica mode (`b`) renders the same state cell-true; pegged stack: Rust — ratatui + crossterm, custom `aurora.rs` (per-cell truecolor gradient field), `glass.rs` (alpha-composite panel fill over pre-blurred aurora), `brackets.rs` (⌜⌝⌞⌟ tick rows), `pulse.rs` (eased animation, DEC 2026 synchronized output), `vtpane.rs` (portable-pty + vt100 grid blit), optional `pixels.rs` (Kitty graphics/Sixel). Glass translucency is replicable because the backdrop is known — per-cell compositing is just math.
- Artifact published at https://claude.ai/code/artifact/24f4c982-8246-4eda-8f4f-82474950986a (update by republishing the same scratchpad fragment path, or pass this URL as `url` from another session).
- Simulating terminal cells in HTML: inline-span backgrounds only paint the font's line box, so with line-height >1 the "cells" render as striped bands — the single ugliest failure mode. Fix: `padding-block` on the spans (≈(line-height−1)/2 em) so backgrounds tile continuously, and paint border rows with the same panel bg so hairlines sit ON the glass. Real terminals never have this problem; the simulation must not either.
- Parity-judge workflow (concept screenshot vs replica screenshot, per screen) scored 72/82 before the fix round; its best catches: rail/pane width ratio (rail ≤ ~26% or transcript lines ellipsize), cards need interior padding rows, statuses want letter-spacing, selection brackets read best as bright ┌ ┐ └ ┘ one cell outside the corners. Judges also hallucinate (state-timing diffs between screenshots, invented color-coding) — verify each claim against the actual concept before applying.
- Task-view verdict from T: the boxed rail + vertical borders + spaced-caps + keycap chips read "college kid" — pivoted to three terminal-native design languages built from a shared engine + fixed content spec (scratchpad/variants/): A MONO (no chrome, whitespace + type levels), B FILL (background-fill slabs, harness stripes, sparklines, zero line borders), C LEDGER (horizontal rules only, asymmetric 24-cell meta column, numbered entries). Ranking panel split: impact and daily-usability lenses both picked B > C > A; brand lens picked C > A > B ("Jobs signs C, rejects B"). A never won a lens — pure minimalism under-signals state for a monitoring UI.
- ANSI→HTML QA renderer bug: joining per-line <div>s with "\n" inside a <pre> makes each newline text node render as a phantom full-height row — invisible on void backgrounds (it flattered MONO/LEDGER with double leading) but it shredded FILL's slabs into stripes. Fix: join divs with no whitespace + integral-pixel cell heights (font 13px/16px, span height 16px). Terminal leading is always 1.0 — any airiness must be designed as whole blank rows, and screenshots with browser line-height lie about it.
- FILL end-to-end build (scratchpad/variants/): fill_system.py (design system + DEMO world) + one module per screen pair + taskai_experience.py (static tour) + live_proto.py (raw-mode interactive TUI, deployed to tmux acp-build:4 as live-proto-claude vs Codex's in :2). Journey-coherence judges beat craft judges: their best catches were product-truth bugs — HUD counting a handoff session as LIVE, three names for one attention state, a handoff screen timestamped after its own clock, keysrow offering "Focus CLI" on the never-live conduit. Cross-frame vocabulary/state consistency is a judging lens of its own; run it whenever multiple screens exist. Overlay frames must composite by slicing the real rendered backdrop rows (SGR-preserving cell slicer) — blank "blur" bands beside a drawer read as an empty product.
